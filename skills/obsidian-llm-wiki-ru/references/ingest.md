# Режим ingest — записать находки в vault

Принцип Karpathy LLM Wiki: каждая сущность на своей странице, связи через `[[wikilinks]]`,
ноль дублирования. Порядок шагов важен: source создаётся первым, потому что остальные
страницы ссылаются на него в `sources:`.

Вызовы ниже даны для MCP (`obsidian_*`). При REST или прямом доступе к файлам —
эквиваленты из `references/access.md`.

## Шаг I. Проверить дубли

Перед созданием **каждой** страницы:

```
obsidian_simple_search("{имя}")       ← страницы ещё нет?
```

Искать по нескольким написаниям: `order-service`, `orderservice`, `OrderService`, русское
название. Нашлась — обновлять её, а не создавать вторую.

## Шаг II. Создать или обновить страницы

Шаблоны — `assets/templates/`. Даты — `YYYY-MM-DD`. Поле `sources:` никогда не пустое:
хотя бы одна ссылка на source-страницу.

| Тип | Путь | Шаблон | Когда |
|---|---|---|---|
| Source (первым) | `sources/{topic}--summary.md` | `source.md` | всегда: отчёт сессии, на него ссылаются остальные |
| Entity | `wiki/entities/{name}.md` | `entity.md` | конкретная вещь: сервис, объект, задача, человек |
| Concept | `wiki/concepts/{slug}.md` | `concept.md` | абстракция: термин, паттерн, механизм, конфиг |
| Lesson | `lessons/{topic}.md` | `lesson.md` | были ловушки, обходные пути, ошибки инструментов |

Tags для concept: `theory | method | field | phenomenon | standard | term | other`.

Существующую страницу **обновлять**, не перезаписывать: дописать факт в нужный раздел,
обновить `updated`, добавить source в `sources:`. Страницу с `reviewed: true` только
дополнять — её проверил человек.

Цитаты из источника — в блок `> **Источник: [[sources/...]]**` дословно. Свой вывод
без источника помечать `HYPOTHESIS`, расхождение документа и реальности — `DOC_GAP`.

### Карта API задачи (опционально)

Задача затрагивает пять и больше методов или сервисов — добавьте в entity задачи раздел
`## Карта API задачи`: таблица «метод → ссылка на спецификацию → факт: проверено /
дефектно / не покрыто, со ссылкой на тест-кейс или трейс». По такой таблице следующая
сессия сразу видит, что уже проверено.

## Шаг III. Cross-links — обязательно в обе стороны

```
entity темы    → [[entities/связанное]], [[concepts/механизм]]
entity сервиса → [[entities/proj-123]]   (обратная ссылка на задачу)
concept        → [[entities/где-используется]]
source         → [[entities/тема]]
```

Ссылка только в одну сторону — полсвязи: со страницы сервиса не видно, какие задачи
его трогали.

## Шаг IV. Cascade — обновить смежные страницы

```
1. obsidian_simple_search("{имя новой сущности}")
   → все страницы, где сущность упоминается текстом
2. для каждой найденной:
   → добавить wikilink, если его ещё нет
   → обновить раздел «Связанные», если нужно
3. обновить wiki/overview.md, если появился новый домен или ключевая сущность
```

Без cascade база копит «мёртвые упоминания»: текст есть, ссылок нет, связь не находится.

Cascade — по **смежным** страницам, обычно 2–5 штук, каждая по делу. Больше 10 файлов
вне задачи — остановиться и спросить (раздел «Массовые операции» в `SKILL.md`).

## Шаг V. Журнал

Дописать в конец `wiki/log.md` (шаблон `assets/templates/log-entry.md`):

```markdown
## [YYYY-MM-DD] ingest | {тема} — краткое описание
**Created:** [[concepts/новое]], [[entities/тема]]
**Updated:** [[entities/X]] (добавлено Y), [[entities/Z]] (cascade cross-link)
**Суть:** одна фраза — что нового узнали
```

Журнал не пересортировывать: только дописывать в конец.

## Шаг VI. Индекс

`wiki/index.md` обновляется на **каждом** ingest. У Карпати это часть ingest и задача
агента, а не отдельного механизма. Файл обычно большой — целиком не читать. Добавить
одну строку (ссылка + однострочное описание) в нужную категорию:

- MCP: `obsidian_patch_content` (target — заголовок категории, вставка после);
- патчинг не работает: дописать в конец в раздел «К сортировке» (`obsidian_append_content`)
  и отметить это в `wiki/log.md`;
- прямой доступ: точечная правка файла под заголовком категории.

Если индекс в вашей базе ведёт плагин, а не агент, — укажите это в
`references/project-config.md` и пропускайте шаг. Сбой инструмента молча не пропускать:
зафиксировать как находку сессии.

## Чеклист ingest

- [ ] `sources/{topic}--summary.md` создан, `type: source`, frontmatter заполнен
- [ ] `wiki/entities/{topic}.md` создан или обновлён
- [ ] entity связанных сервисов и объектов обновлены
- [ ] новые concepts созданы (если были новые термины)
- [ ] lesson записан (если были ловушки)
- [ ] **cascade:** смежные страницы найдены поиском и обновлены
- [ ] cross-links в обе стороны
- [ ] запись в `wiki/log.md`
- [ ] нет страниц с пустым `sources: []`
- [ ] findability-чеклист пройден (`SKILL.md`)
- [ ] строка в `wiki/index.md` добавлена (или зафиксирован сбой инструмента)
- [ ] страницы с `reviewed: true` только дополнены
- [ ] вне задачи изменено не больше 10 файлов (иначе — согласовано)

## Итог для пользователя

Короткий список: какие страницы созданы, какие обновлены (и чем), что ушло в cascade,
что не удалось (с причиной). Числа — сколько файлов тронуто.
