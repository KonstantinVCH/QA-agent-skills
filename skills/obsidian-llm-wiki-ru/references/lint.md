# Режим lint — проверить здоровье базы

Запускать каждые 5–10 ingest-операций или по просьбе («проверь базу», «битые ссылки»).

## Как собрать список проблем

- **Прямой доступ к файлам** — `scripts/wiki_lint.py` собирает механические проблемы
  за один проход и ничего не правит:

  ```bash
  python scripts/wiki_lint.py --vault "$OBSIDIAN_VAULT" --out lint.json
  python scripts/wiki_lint.py --vault "$OBSIDIAN_VAULT" --scope wiki/entities   # только папка
  ```

  Ссылки внутри `` `кода` `` и блоков ```` ``` ```` скрипт не считает — там примеры
  синтаксиса. Отчёт строится по страницам графа (с полем `type` во frontmatter);
  рабочие заметки без `type` пропускаются, `--all-pages` включает их. Папку шаблонов
  страниц исключайте (`--exclude templates`): шаблоны с плейсхолдерами дают ложные
  сироты и совпадения aliases.

  Скрипт выдаёт **кандидатов**. Каждый пункт перед автофиксом проверьте глазами:
  например, `duplicate_names` и `alias_collisions` бывают законными (общий термин
  у двух страниц).
- **Только MCP/REST** — то же вручную: список файлов (`obsidian_list_files_in_dir`),
  чтение страниц, поиск упоминаний. Ограничьте область (папка, тема), иначе lint
  съест контекст.

## Что проверяется

**Автофикс (делать сразу):**

- страница есть, но не упомянута в `wiki/log.md` / `wiki/overview.md` / `wiki/index.md` →
  добавить ссылку;
- `[[wikilink]]` ведёт в несуществующий файл → найти по имени и исправить путь;
  не нашлась — пометить `[MISSING]`;
- страница из `sources:` не существует → пометить `[MISSING]`;
- очевидные недостающие cross-links между связанными страницами → добавить.

**Только отчёт (не автофиксить):**

- страницы без входящих ссылок (сироты) — перечислить;
- противоречия между страницами — перечислить, с атрибуцией: где что сказано;
- пустой `sources: []` — перечислить;
- концепты и сущности, которые часто упоминаются, но своей страницы не имеют, — перечислить;
- вероятные двойники (`order-service` и `orderservice`) — перечислить.

Автофикс — это правки в пределах явных поломок. Ограничения из раздела «Массовые
операции» в `SKILL.md` действуют и здесь: больше 10 файлов — сначала назвать объём
и спросить. Заглушки «Stub created by…» вместо починки не создавать.

## После lint

Дописать в конец `wiki/log.md`:

```markdown
## [YYYY-MM-DD] lint | N issues, M auto-fixed
**Auto-fixed:** ...
**Report:** ...
```

Пользователю — отчёт: что исправлено (файлы, число правок), что требует решения человека.
