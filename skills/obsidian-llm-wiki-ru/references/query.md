# Режим query — ответить из vault

**Query никогда не пишет файлы сам.** Только читает и отвечает в чат.

## Процесс

1. Preflight (`SKILL.md`, раздел «Доступ к vault»).
2. Прочитать `wiki/overview.md` — точка входа, архитектура домена.
3. Найти релевантные страницы: `obsidian_simple_search("{тема}")` по конкретным терминам,
   не по общим словам (широкий запрос переполняет контекст).
4. Прочитать найденные страницы. По wikilinks перейти на один уровень, если нужно.
5. Синтезировать ответ **из vault**, не из общих знаний модели. Каждое утверждение —
   со ссылкой: `[[entities/order-service|Order Service]]`.
6. Перед выводом «в базе нет информации» — поискать по 2–3 синонимам: рус + англ +
   аббревиатура (`заказ`, `order`, `OMS`).

## Формат ответа

- Сначала прямой ответ на вопрос.
- Затем факты со ссылками на страницы-источники.
- Отдельно: что в базе помечено `HYPOTHESIS` или `DOC_GAP`, и чего в базе нет вовсе.
  Пробел в базе — тоже результат: его можно закрыть следующим ingest.
- Общие знания модели, если без них не обойтись, — явно пометить как не из базы.

## «Сохрани ответ»

Пользователь просит сохранить или архивировать ответ — это уже запись, режим меняется
на ingest. Создать `sources/{slug}--query-answer.md` с `type: source`, добавить запись
в `wiki/log.md` (операция `query`), при необходимости cascade.
