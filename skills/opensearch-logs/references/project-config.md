# Настройка под проект — шаблон

Заполни один раз и держи рядом со скиллом (или в базе знаний проекта). Всё, что ниже в фигурных
скобках, — плейсхолдеры. Скрипты читают значения из переменных окружения; таблица показывает,
какая переменная за что отвечает.

## 1. Системы и доступ

| Что | Значение | Переменная окружения |
|---|---|---|
| Kibana / OpenSearch Dashboards тестовых стендов | `{OPENSEARCH_URL}` | `OPENSEARCH_URL` |
| Транспорт поиска | `kibana` / `console` / `direct` | `LOGS_API` |
| Kibana прода (если есть, отдельный хост) | `{OPENSEARCH_PROD_URL}` | — (только по явному запросу) |
| Jaeger | `{JAEGER_URL}` | `JAEGER_URL` |
| Хост SSO (SAML/ADFS), если вход только через браузер | `{SSO_HOST}` | `SSO_HOST` |
| Bamboo (для разбора упавших деплоев) | `{BAMBOO_URL}` | `BAMBOO_URL` |
| Токен Bamboo | personal access token | `BAMBOO_TOKEN` |
| Токен/логин к логам, если доступ не анонимный | — | `OPENSEARCH_TOKEN` или `OPENSEARCH_USER` + `OPENSEARCH_PASSWORD` |
| Самоподписанный TLS-сертификат | да / нет | `OPENSEARCH_INSECURE=1` |

Где брать токены: Bamboo — Profile → Personal access tokens; OpenSearch/Kibana — у владельцев
кластера (сервисная read-only учётка или API key). Токены не коммитить и не вставлять в
аргументы команд — только переменные окружения или менеджер секретов.

Нужен ли VPN и какой: `{VPN}` (например: «корпоративный для Kibana, отдельный для SSO-входа»).
Симптом отсутствия VPN — connection timeout, а не 401.

## 2. Индексы и data view

| Что | Значение | Переменная |
|---|---|---|
| Индексы с логами (все наборы, через запятую) | `{INDEX_1},{INDEX_2}` (пример: `logs-app-*,logs-infra-*`) | `LOGS_INDEX` |
| id data view (index-pattern) для ссылок Discover | `{префикс1}={id1},{префикс2}={id2}` | `LOGS_DATA_VIEWS` |
| Tenant OpenSearch Dashboards для ссылок | `{TENANT}` (часто `global`) | `LOGS_DISCOVER_TENANT` |
| Ретеншн логов | `{N}` суток (измерено гистограммой, дата замера) | — |
| Ретеншн Jaeger | `{N}` суток | — |

id data view: Kibana → Stack Management → Data Views → открыть нужный → id в адресной строке.
Если наборов индексов несколько (например, приложения и инфраструктура лежат отдельно) —
перечисли все: поиск в одном наборе отдаёт ноль на живых логах другого, и это неотличимо от
«сервис молчал».

## 3. Поля

| Смысл | Поле в вашем индексе | Переменная | Значение по умолчанию |
|---|---|---|---|
| namespace (точное значение) | `{…}` | `LOGS_NS_FIELD` | `kubernetes.namespace.keyword` |
| имя контейнера (точное) | `{…}` | `LOGS_CONTAINER_FIELD` | `kubernetes.container.name.keyword` |
| имя под-а (точное) | `{…}` | — | `kubernetes.pod.name.keyword` |
| класс-источник (logger, точное) | `{…}` | `LOGS_LOGGER_FIELD` | `logger.keyword` |
| уровень | `{…}` | `LOGS_LEVEL_FIELD` | `level` (в ECS — `log.level`) |
| полный stacktrace | `{…}` | `LOGS_STACK_FIELD` | `trace` (в ECS — `error.stack_trace`) |
| текст события (все варианты) | `{…}` | `LOGS_TEXT_FIELDS` | `message,messagetext` |
| traceId (все варианты) | `{…}` | `LOGS_TRACE_FIELDS` | `traceId,trace_id,trace.id` |
| контейнеры с неразобранными логами | `{…}` (пример: `db-migrator`) | `LOGS_RAW_CONTAINERS` | пусто |

Как узнать реальные поля: запросить одну запись без `_source`-фильтра и посмотреть ключи
(см. `query-cookbook.md`, «Поле не то»).

## 4. Стенды

| Что | Значение | Переменная |
|---|---|---|
| Как номер стенда превращается в namespace | `{шаблон}` (пример: `testing-{stand}`) | `LOGS_NAMESPACE_TEMPLATE` |
| Нестандартные стенды и их namespace | `stable → {namespace}` | передавать полным именем в `--stand` |
| Как сервис называется в Jaeger | `{шаблон}` (пример: `testing-{stand}.{service}`) | `JAEGER_SERVICE_TEMPLATE` |
| Совпадают ли имена индексов теста и прода | да / нет | — |

Если имена индексов на тесте и проде совпадают, отличается только хост — перед любым выводом
«это прод» сверять хост, а не индекс.

## 5. Сервисы

Имя контейнера обычно равно имени сервиса в нижнем регистре. Запиши карту, чтобы не угадывать:

| Сервис (как называют в задачах) | Контейнер | Что делает |
|---|---|---|
| `{OrderService}` | `{order-service}` | `{…}` |
| `{PaymentService}` | `{payment-service}` | `{…}` |
| `{…}` | `{db-migrator}` | джоба миграций БД при деплое |

Ключевая цепочка запроса (для поиска по traceId): `{frontend} → {api-gateway} → {order-service} → …`

## 6. База знаний проекта (необязательно)

Если у команды есть база знаний (вики, Obsidian-vault в git, Confluence) с разборами прошлых
падений — укажи, где искать: `{URL или путь}`, по какому ключу (`{номер задачи}`, имя сервиса).
Скилл обращается к ней, когда логи уже вычищены ретеншном.
