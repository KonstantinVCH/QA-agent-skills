# Настройка под проект — шаблон

Заполни один раз. Всё в фигурных скобках — плейсхолдеры. Скрипты читают значения из
переменных окружения; таблицы показывают, какая переменная за что отвечает.

## 1. Системы и токены

| Что | Значение | Переменная окружения |
|---|---|---|
| Bamboo | `{BAMBOO_URL}` | `BAMBOO_URL` |
| Токен Bamboo | personal access token | `BAMBOO_TOKEN` |
| Bitbucket Server / Data Center | `{BITBUCKET_URL}` | `BITBUCKET_URL` |
| Токен Bitbucket | HTTP access token | `BITBUCKET_TOKEN` |
| Jira (ключ проекта задач) | `{PROJ}` | `TASK_KEY_PREFIX` |
| Проект Bitbucket с сервисами | `{SERVICES_PROJECT}` | — |

Токены создаются в профиле пользователя:
- Bamboo → Profile → Personal access tokens → Create token;
- Bitbucket → Manage account → HTTP access tokens → Create token (права Projects/Repositories:
  Read; Write — только если скилл будет создавать ветки-алиасы в репозитории конфигурации).

**Токены раздельные:** Bamboo-токен в Bitbucket не работает и наоборот (401). Basic-авторизация
логином/паролем на Bamboo REST при SSO тоже даёт 401. Токены не коммитить и не передавать
аргументами — только переменные окружения или менеджер секретов.

## 2. Стенды — что можно катить

| Что | Значение | Переменная |
|---|---|---|
| Тестовые стенды, на которые скилл катит сам | `{1..5}` | — |
| Имя окружения Bamboo для стенда | `{Testing-{stand}}` | `DEPLOY_ENV_TEMPLATE` |
| Окружения, на которые скилл не катит НИКОГДА | `{prod, production, stable, pre-prod, …}` | — |

Список запрещённых окружений — защита от самой дорогой ошибки скилла. Впиши сюда все имена,
под которыми у вас живут прод и предпрод, включая сокращения.

## 3. Сервисы и деплой-проекты Bamboo

| Что | Значение |
|---|---|
| Шаблон имени деплой-проекта | `{"Services - {svc}"}` (сравнивать в lower-case) |
| Исключения из шаблона | `{frontend → "Services - Frontend"}` |
| Репозитории — не сервисы (не деплоятся сами) | `{deploy-config}`, `{db-migrator}`, `{shared-lib}` |
| Особые имена веток задачи | `{frontend: feature/{TASK}}` |
| Стоп-кран: веток задачи больше чем | `15` репозиториев → показать список, переспросить |

Кэш ID (стабильны; не совпало — пересчитать через `deploy/project/all`):

| Сервис | projectId | planKey | стенд-1 envId | стенд-2 envId | … |
|---|---|---|---|---|---|
| `{order-service}` | `{…}` | `{BUILDS-ORDERSVC}` | `{…}` | `{…}` | |
| `{payment-service}` | `{…}` | `{…}` | `{…}` | `{…}` | |

## 4. Репозиторий конфигурации деплоя (если есть)

Заполняй, только если деплой-скрипт подхватывает ветку конфигурации по имени релиза
(см. `config-branch.md`).

| Что | Значение | Переменная |
|---|---|---|
| Репозиторий конфигурации | `{DEVOPS/deploy-config}` | `CONFIG_REPO` |
| Основная ветка | `{master}` | — |
| Какие имена веток находит автоподбор | `{PROJ-123}`, `{feature-PROJ-123}`, `{feature/PROJ-123}` | — |
| Строка лога «ветка найдена автоподбором» | `{…}` | `BRANCH_AUTO_RE` |
| Строка лога «ветка задана вручную» | `{…}` | `BRANCH_PINNED_RE` |
| Строка лога «деплой выполняется из ветки» | `{…}` | `BRANCH_FINAL_RE` |
| Переменная окружения деплоя, жёстко задающая ветку | `{config_branch}` | `CONFIG_BRANCH_VAR` |
| Пути сервиса в репозитории (по ним видно «у кого конфиг в ветке») | `{group_vars/<svc>/…}`, `{templates/<svc>/…}` | — |
| Пути — не сервисы | `{all}`, `{common-templates}` | — |
